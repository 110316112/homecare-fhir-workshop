# 學員提示詞（Q1、Free-style、完整規格版）

> CSV 已更新為 9 欄（新增 selectionType）。舊的 8 欄版本不能再用。

## Q1：產生 detail CSV

### 提示詞（整段貼給 AI，`oral-ulcer`、`口腔潰瘍` 可換成其他問題）

````
請參考下面的 pain detail CSV 規格，為「oral-ulcer（口腔潰瘍）」產生 detail CSV。

規則：
1. 第一列標題列必須完全一樣：problemCode,detailCode,detailName,detailNameEn,valueType,selectionType,valueCode,valueDisplay,valueDisplayEn
2. 每一列剛好 9 個欄位，欄位內容不要含逗號與引號
3. problemCode 每列都填 oral-ulcer
4. 設計 5 到 8 個 detailCode（例如位置、外觀、大小、疼痛程度、持續時間、誘發因素、伴隨症狀），detailCode 用英文 camelCase
5. 同一個 detailCode 的每個選項各一列，每個項目 3 到 6 個選項，detailName、detailNameEn、selectionType 在同一個 detailCode 的各列要相同
6. selectionType 只能填 single（單選）或 multiple（多選）
7. valueType 填 code；若是要輸入數字，valueType 填 quantity、selectionType 填 single，且 valueCode、valueDisplay、valueDisplayEn 三欄留空
8. valueCode 用英文小寫與連字號；valueDisplay 用繁體中文；valueDisplayEn 用英文
9. 只輸出一個 CSV 程式碼區塊，不要任何說明

pain 範例：
problemCode,detailCode,detailName,detailNameEn,valueType,selectionType,valueCode,valueDisplay,valueDisplayEn
pain,severity,嚴重程度,Severity,code,single,mild,輕度,Mild
pain,severity,嚴重程度,Severity,code,single,moderate,中度,Moderate
pain,bodySite,發生部位,Body Site,code,multiple,head,頭部,Head
pain,quality,疼痛模式,Pain Quality,code,multiple,sharp,刺痛,Sharp pain
pain,frequency,發生頻率,Frequency,code,single,intermittent,間歇性,Intermittent
pain,aggravating,加重因素,Aggravating Factor,code,multiple,movement,活動,Movement
````

```
請逐列檢查你剛才的 CSV：標題列是否與 pain 範例完全相同、是否每列剛好 9 欄、是否有欄位含逗號、同一個 detailCode 的 detailName 與 selectionType 是否一致、selectionType 是否只有 single 或 multiple。有問題請直接輸出修正後完整的 CSV，沒有問題請回答「檢查通過」。
```


## Free-style（老師的 Exp 2，刻意簡短，用來比較）


```
FHIR server 為 https://hapi.fhir.org/baseR4。請提供一可輸入疼痛細節紀錄，並產生 FHIR observation 的 HTML 網頁程式，HTML、JS、CSS 寫在一起，使用單純的 JS 語法。此量測參考的病人為 FHIR Patient.id = "7158c01b-32ba-4fbd-a038-201a0a2a4e2a"，量測時間抓取電腦目前時間。並回應調閱 URL。
```

沒有給 CSV，每個人的結果會不一樣。


## 完整規格版


````
FHIR server 為 https://hapi.fhir.org/baseR4。請寫一個單一 HTML 檔，HTML、JS、CSS 寫在一起，只用單純 JavaScript，不使用外部套件。

病人 Patient.id 預設為 7158c01b-32ba-4fbd-a038-201a0a2a4e2a，紀錄時間預設為電腦目前時間（datetime-local）。

功能：
1. 輸入框填 DocumentReference URL，按「讀取規格」後，GET 此網址，取出 content[0].attachment.data，用 atob 加 TextDecoder("utf-8") 解碼成 CSV 文字
2. CSV 標題列為 problemCode,detailCode,detailName,detailNameEn,valueType,selectionType,valueCode,valueDisplay,valueDisplayEn，要自己寫 CSV 解析（支援雙引號與 BOM）
3. 依 detailCode 分組。每個 detailCode 顯示一個 checkbox 與名稱；valueType 為 code 的，selectionType 為 single 用 radio button 選一個 valueCode，multiple 用 checkbox 可選多個（顯示 valueDisplay）；valueType 為 quantity 或 integer 的用數字輸入框
4. 按鈕 1：產生 Observation JSON 顯示在 textarea。格式：resourceType Observation、status final、category（observation-category 的 survey）、code（coding 的 code 為 problemCode）、subject 為 Patient/病人ID、effectiveDateTime、component 陣列。每個被勾選的項目一筆 component：code.coding 放 detailCode 與 detailName；選項放 valueCodeableConcept（coding 放 valueCode 與 valueDisplay，多選時 coding 放多筆，並有 text）；數字放 valueQuantity 或 valueInteger
5. 按鈕 2：把 textarea 的 JSON 用 HTTP POST（Content-Type application/fhir+json）送到 https://hapi.fhir.org/baseR4/Observation，回應顯示在另一個 textarea
6. 上傳成功後，用回應的 id 組出 https://hapi.fhir.org/baseR4/Observation/{id} 並顯示
7. 所有 fetch 都用 try/catch，錯誤訊息顯示在畫面上
只輸出完整 HTML 程式碼。
````

結果會比 Free-style 接近，但不保證完全一致。請用下方的驗收清單檢查。

驗收清單：

- [ ] 讀取規格後，每個 `detailCode` 都有出現
- [ ] `single` 的項目是單選按鈕，`multiple` 的項目是勾選框，項目前有勾選框
- [ ] 產生的 JSON 有 `resourceType`、`status`、`code`、`subject`、`effectiveDateTime`、`component`
- [ ] 上傳後有 HTTP 201，並顯示 Observation 網址
- [ ] 用網址開啟，內容與選擇一致
