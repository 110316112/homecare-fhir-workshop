# 學員提示詞（Q1 與 Q4）

## Q1：產生 detail CSV（請把 oral-ulcer、口腔潰瘍換成你要做的問題）

```
請參考下面的 pain detail CSV 規格，為「oral-ulcer（口腔潰瘍）」產生 detail CSV。

規則：
1. 第一列標題列必須完全一樣：problemCode,detailCode,detailName,detailNameEn,valueType,valueCode,valueDisplay,valueDisplayEn
2. 每一列剛好 8 個欄位，欄位內容不要含逗號與引號
3. problemCode 每列都填 oral-ulcer
4. 設計 5 到 8 個 detailCode（例如位置、外觀、大小、疼痛程度、持續時間、誘發因素、伴隨症狀），detailCode 用英文 camelCase
5. 同一個 detailCode 的每個選項各一列，每個項目 3 到 6 個選項，detailName 與 detailNameEn 在同一個 detailCode 的各列要相同
6. valueType 填 code；若是要輸入數字，valueType 填 quantity，且 valueCode、valueDisplay、valueDisplayEn 三欄留空
7. valueCode 用英文小寫與連字號；valueDisplay 用繁體中文；valueDisplayEn 用英文
8. 只輸出一個 CSV 程式碼區塊，不要任何說明

pain 範例：
problemCode,detailCode,detailName,detailNameEn,valueType,valueCode,valueDisplay,valueDisplayEn
pain,severity,嚴重程度,Severity,code,mild,輕度,Mild
pain,severity,嚴重程度,Severity,code,moderate,中度,Moderate
pain,bodySite,發生部位,Body Site,code,head,頭部,Head
pain,quality,疼痛模式,Pain Quality,code,sharp,刺痛,Sharp pain
pain,frequency,發生頻率,Frequency,code,intermittent,間歇性,Intermittent
pain,aggravating,加重因素,Aggravating Factor,code,movement,活動,Movement
```

### 產生後的檢查提示詞（接著貼給同一個 AI）
```
請逐列檢查你剛才的 CSV：標題列是否與 pain 範例完全相同、是否每列剛好 8 欄、是否有欄位含逗號、同一個 detailCode 的 detailName 是否一致。有問題請直接輸出修正後完整的 CSV，沒有問題請回答「檢查通過」。
```
存成 `xxx_detail.csv`，編碼用 UTF-8。

## Q4 Free-style（老師的 Exp 2，刻意簡短，用來比較）

```
FHIR server 為 https://hapi.fhir.org/baseR4。請提供一可輸入疼痛細節紀錄，並產生 FHIR observation 的 HTML 網頁程式，HTML、JS、CSS 寫在一起，使用單純的 JS 語法。此量測參考的病人為 FHIR Patient.id = "7158c01b-32ba-4fbd-a038-201a0a2a4e2a"，量測時間抓取電腦目前時間。並回應調閱 URL。
```
這個提示詞沒有給 CSV 規格，每個人會得到不同結構的 Observation。

## Q4 完整規格版（希望 AI 做出和教學範例一樣能運行的程式）

```
FHIR server 為 https://hapi.fhir.org/baseR4。請寫一個單一 HTML 檔，HTML、JS、CSS 寫在一起，只用單純 JavaScript，不使用外部套件。

病人 Patient.id 固定預設為 7158c01b-32ba-4fbd-a038-201a0a2a4e2a，紀錄時間預設為電腦目前時間（datetime-local）。

功能：
1. 輸入框填 DocumentReference URL（預設 https://hapi.fhir.org/baseR4/DocumentReference/92286468-30cd-411d-84f5-7d747dea8d30），按「讀取規格」後，GET 此網址，取出 content[0].attachment.data，用 atob 加 TextDecoder("utf-8") 解碼成 CSV 文字
2. CSV 標題列為 problemCode,detailCode,detailName,detailNameEn,valueType,valueCode,valueDisplay,valueDisplayEn，要自己寫 CSV 解析（支援雙引號與 BOM）
3. 依 detailCode 分組。每個 detailCode 顯示一個 checkbox 與名稱；valueType 為 code 的用 radio button 選一個 valueCode（顯示 valueDisplay）；valueType 為 quantity 或 integer 的用數字輸入框
4. 按鈕 1：產生 Observation JSON 顯示在 textarea。格式：resourceType Observation、status final、category（observation-category 的 survey）、code（coding 的 code 為 problemCode）、subject 為 Patient/病人ID、effectiveDateTime、component 陣列。每個被勾選的項目一筆 component：code.coding 放 detailCode 與 detailName；選項放 valueCodeableConcept（coding 放 valueCode 與 valueDisplay，並有 text）；數字放 valueQuantity 或 valueInteger
5. 按鈕 2：把 textarea 的 JSON 用 HTTP POST（Content-Type application/fhir+json）送到 https://hapi.fhir.org/baseR4/Observation，回應顯示在另一個 textarea
6. 上傳成功後，用回應的 id 組出 https://hapi.fhir.org/baseR4/Observation/{id} 並顯示
7. 所有 fetch 都用 try/catch，錯誤訊息顯示在畫面上
只輸出完整 HTML 程式碼。
```
說明：這個版本把結構都講清楚，不同 AI 的結果會很接近，但不保證完全一致。請用「驗收清單」逐項檢查。

## 驗收清單（學員自己檢查 AI 做的網頁）
- 讀取規格後，每個 detailCode 都有出現
- 選項是 radio、項目前有 checkbox
- 產生的 JSON 有 resourceType、status、code、subject、effectiveDateTime、component
- 上傳後有 HTTP 201，並顯示 Observation 網址
- 用網址開啟，內容與選擇一致
